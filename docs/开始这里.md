# 开始这里

这套仓库把同一份 3D 资产从需求、Blender 生产、GLB 门禁，送到 Godot 游戏和 Web 查看器。所有关键资产都能由固定种子 42 重建，不依赖失效的系统 `py` 命令，也不需要云端服务。

## 先看成果

1. 双击根目录的 `启动完整演示.cmd`。Godot 会打开可玩的第三人称庭院，浏览器会打开同一套 GLB 的 Web 查看器。
2. Godot：`WASD` 移动，`Shift` 奔跑，`Space` 跳跃，`L` 切换昼夜，鼠标拖动相机。
3. Web：拖动旋转、滚轮缩放；点击 Idle、Walk、Run、Jump 切换四段动画；还可切换配色和昼夜。
4. 双击 `打开CAD审阅.cmd`，在 3245 端口用实体/线框方式审阅环境和角色 GLB。

## 三个稳定入口

- 环境检查：`powershell -File tools/doctor.ps1`
- 确定性重建：`powershell -File tools/build-asset.ps1 -Asset future_courtyard -Stage all`
- 全部验收：双击 `运行总验收.cmd`，或运行 `powershell -File tools/verify-all.ps1 -Asset future_courtyard`
- 固定版 Codex：`powershell -File tools/codex-project.ps1`，始终从本仓库启动官方稳定版 0.151.0 并加载项目 MCP。

重建不会直接覆盖合格资产。Blender 先写 `build/candidates`，验证预算、命名、动画和 GLB 完整性后，才提升到 `assets/runtime`。四个 `.blend` 检查点分别保留 blockout、geometry、material/animation 和 export 状态。

## 修改一次，看三端同步

打开 `assets/briefs/future_courtyard.brief.json`，把 `palette.accent` 改成另一个十六进制颜色。运行重建和总验收，再重启 Godot/Web/CAD。三个运行端读取的是同一对规范 GLB；`assets/manifests/future_courtyard.manifest.json` 会记录新的 SHA-256，避免“看起来更新了、实际仍在用旧文件”。

## 工作流图

`brief → Blender 脚本 → 四阶段检查点 → candidate GLB → G4 门禁 → runtime GLB → Godot / Web / CAD → G5–G7 证据`

先看现成结果，再改一个颜色，然后完成 `学习挑战.md`。这是“逆向拆解 → MVP → 费曼复述”的学习顺序。
